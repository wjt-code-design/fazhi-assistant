## 3. 五问对抗（vet-plan）

**① 模块边界自然吗？**
两个候选落点都是**共享路径**：
- `query_understand.decompose`（锚点抽取）：单一职责、已被 `hybrid_retrieve` 消费，接口天然；
  代价是同时影响 Fast Path。
- `retrieval.hybrid_retrieve`（多查询扇出）：只影响检索层，但会把"分解"逻辑与"检索"逻辑混在一处。
倾向 decompose（边界更自然），**但以 P1 证据定**。

**② 有没有更优解？（至少两个替代）**
| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 甲 扩展锚点抽取 | 让 `decompose` 除罪名外也抽**法律概念锚点**（如"不能胜任工作""调岗""工会程序"），复用既有**锚点保底**机制 | 改动局部；收益由既有机制保证（每锚点 top-3 必进结果） | 影响共享路径；词表需防过匹配 |
| 乙 Agent 层多查询扇出 | 每个争点/概念各发一次 `retrieve_laws` 再合并 | 不改共享路径；每查询聚焦 | 受 `max_tool_calls=10`（每 run）与 steps 上限约束；增加步数与远程调用；**C01 已用 3/10** |

## 4. 代理目标声明（最隐蔽的坑）

D2 测的是**召回命中率**，它代理的是"闸门**有机会**通过"，
**不是**"答案法律正确"。命中 4/4 也可能是引对了条文、援引错了适用条件。
⇒ 保留 H3 的语义复核流程（机械结果 + 独立复核 + REVIEW 分开记），不用召回率替代法律质量。
