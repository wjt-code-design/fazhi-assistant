## ① 检索召回质量审查（grilling 建议①）

### 问题复现与根因定位（全部实证，未猜测）

**现象**（T5 报告已记录）：C07 民事借款时效案终稿引用《行政诉讼法》49/51条（应适用民诉法）；C10 民刑分流案证据池混入《刑事诉讼法》101/103条。

**证据层定位**（`agent_evidence` 表，provenance 字段揭示真实来源）：
- C07 「起诉条件」issue 证据池：`行政诉讼法#第四十九条` + `民事诉讼法#第一百二十二条`（两条都是"起诉须符合条件"语义条文）
- C10 「不当得利/诈骗边界」issue 证据池：`刑事诉讼法#103/101`（附带民事诉讼）+ 消保法 + 专利法混入
- 结论：**跨部门法语义相似条文被 Agent 子查询召回进证据池**（rerank 判高分），writer 确定性校验只验证"引用存在于绑定证据"（通过），**无部门法适用性校验**。

**检索层实测复现**（`retrieve()` 直调，本地 embedding + 免费 rerank，零成本）：
```
Q: 民事借款纠纷 诉讼时效 起诉条件 需要什么条件才能起诉
top-6: 民法典188/195/192/190/194 + 民事诉讼法122（无行政诉讼法 → 主 query 召回干净）
```
→ **检索算法本身正确**（recall 干净）；混入发生在 Agent 将其拆分出的子问题（如"起诉条件"孤立查询）+ `category=None` + rerank 语义近判定时。

**知识库 metadata 实测**：字段仅 `article/chapter/effective_from/effective_to/file_hash/origin/source/status`——**有法名（source）字段，无部门法（category）标签**，检索链路无按部门法过滤的能力。

### 结论（"可修 or 边界"判定）

| 层 | 判定 | 依据 |
|---|---|---|
| 检索算法（向量/BM25/RRF/rerank） | ✅ 正确 | 主 query 直接召回全民事法条 |
| 知识库部门法标签 | ❌ 缺失 | metadata 无 category，无法按部门法过滤 |
| Agent 子查询 × rerank | ⚠️ 结构性缺陷主因 | 子问题孤立化 + 语义近判定引入跨部门法条文 |
| writer/verifier 适用性校验 | ⚠️ 不校验部门法适用性 | 仅校验引用在绑定证据内（确定性），facility 单一 |

**判定：非本轮可同行改的 bug，属语义/知识库层结构性限制**。修复路径（须预注册评估）：
- 方向 A：知识库批量补部门法标签（metadata.category）+ 按案型部门法白名单过滤
- 方向 B：Agent 子查询阶段强制带案型部门法约束（tools 层）
两者均为行为变更，按项目纪律需先预注册 + 双集验证（防过拟合），非顺手改。**本轮不擅动 backend（与前端优化解耦）。**
