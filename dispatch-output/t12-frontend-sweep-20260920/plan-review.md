## 偏差二：§0-C/§1-③ 承诺的「错误码层」**首轮漏做**（本轮补齐）

- 计划书两处明写深口径含「**③ 代码级错误码 + SSE 帧形状**」，理由是"浅口径覆盖不到错误码 = 假结论"。
- **实际首轮**：只做了 SSE 帧类型（报告 §3.2），**HTTP 状态码层没系统比对** ⇒ 报告当时若声称"深口径完成"就是**过度声称**。
- **本轮补齐**（报告新增 §3.4）：
  - 后端状态码全集：**401**（`main.py:389`；`auth.py:60/64/67`）、400×15、404×14、503×4、501×2、413×2、409×2、403×2、502×1（+ FastAPI 隐式 422）；
  - 前端：**仅 401 特殊**（清 token + 跳 `/login`），其余 `!res.ok` → 解析 `detail`；
  - **判定：无不一致**（前端是宽契约）。
  - 附带观察：openapi **只声明 200/422，业务码未声明** ⇒ 若要用 openapi 生成客户端/文档，关键端点应补 `responses`。
- **过程中的二次自我纠错**：我第一遍 grep 状态码用了 `head -8`，把 **401 截掉了**，一度以为"后端不发 401"；
  补查 `auth.py` 后才确认 401 存在。⇒ 教训：**用 `head` 截断计数输出会让"不存在的结论"凭空成立**。
