## §D 超出声明表的实质风险（必须报告）

### D.1 `datetime.UTC` 导入 vs 代码自述的 Python 3.10 部署环境

19:40 的批量改动中含 ruff `UP017` 类自动修复，产生了**语义改动**（非纯格式化）：

```python
# backend/auth.py 当前内容（L2、L4）
from datetime import UTC, datetime, timedelta

UTC = UTC  # Python 3.10 兼容：datetime.UTC 需 3.11+，服务器为 3.10
```

- 原内容为 `UTC = timezone.utc`，配套注释明确写着**"服务器为 3.10"**。
- `datetime.UTC` 是 **Python 3.11+** 才有的别名 ⇒ **若部署环境确为 3.10，将在模块导入期抛 `ImportError`**。
- `backend/scripts/gate2_runner.py` 同样新增了 `from datetime import UTC`（付费轮驱动脚本）。
- 本机 venv 实测为 **Python 3.11.0**（`datetime.UTC 可用 = True`）
  ⇒ **A3 的 924 passed 完全无法暴露该风险**，不能用作反证。

**该改动未被任何声明覆盖**（A1 的 changed=15 清单里含 `gate2_runner.py`，但 `auth.py` 属那 122 个"新增"文件之一，
即验收包声称"不存在"的那一批）。

**建议**：确认目标部署版本。若为 3.10，须回退这两处 UP017 修复；若已升级到 3.11，须**同步更新 auth.py L4 的过期注释**
（注释与代码现已自相矛盾：注释说要兼容 3.10，代码用了 3.11 才有的 API）。
