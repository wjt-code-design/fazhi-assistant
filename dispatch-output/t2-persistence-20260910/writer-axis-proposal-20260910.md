## §1 结论先行：墙不在 writer，在检索/链接侧 —— T7 的因果链判断错误

T7 验收报告曾说："分解已读、检索 4/4 全中，**writer 不引要件法条**"（10/10 full_closure 全灭的归因）。

本轮用 judge 自己的规范化（`gate5_judge._extract_citations`，冻结权威口径）对 **run-14 + run-15 全部
57 个 required-law 实例**逐条判定断链层，结果：

| 断链层 | 数量 | 占比 |
|---|---|---|
| **HIT**（终稿引用了） | 18 | 32% |
| **WRITER_MISS**（证据里有、终稿没引） | **0** | **0%** |
| **EVIDENCE_MISS**（证据里根本没有） | **39** | **68%** |

**writer/渲染侧零失误**：57 个样本里，凡进入 state 证据的成文法，writer **全部**以规范
`《法名》第X条` 形式渲染进终稿（C07 终稿 14 处引用全部规范，见 §3 实例）。
**墙 100% 在"required 法条是否进入证据"——即检索/链接侧。**

> 探针本身的教训（如实记）：本次分析我先后犯了两处探针错误（`final_answer` 键名不存在、
> `source_type` 大小写），**都靠"先怀疑自己的探针"兜住**——若直接相信第一次结果，
> 就会把墙错怪在 writer 头上并去改冻结的提示词。

## §3 单案机制实例（run-16 C07，实测）

C07 required = 民法典 188 / 195 / 675：
- 证据（8 条 statute，全 effective）：民法典 192/195/189 + 民诉法 250/122/126/127 + 行诉法 49
  ⇒ **195 在，188/675 不在**
- 终稿：**8 条证据全部以规范形式渲染**（《民法典》第一百九十五条 等共 14 处引用）
- full_closure 判定：missing = [民法典:188, 民法典:675] ⇒ 不过

⇒ writer 把"手里有的"全引了；缺的是"没喂给它的"。

## §4 根因假设（按证据强度排序，均待立项验证）

1. **k=4 截断 + 排序**（强）：每 issue 只取 top-k，required 条文排名靠后即被截断。
2. **query 与法条词汇不匹配**（强）：issue 问句（"是否过时效"）与目标条文措辞（"普通诉讼时效期间三年"）
   词汇重叠低，向量召回不中。
3. **分解未覆盖产生该法条的子争点**（中）：C07 分解只出"时效 + 起诉条件"两个争点，
   没有"借款合同履行/期限"子争点 ⇒ 675 无从被检索。
4. **确定性补充通道缺失**（中，且是修复路径）：现有 `domain_rules.py` 已有"场景关键词 → 法条文档"
   的确定性补充模式（`consumer_clause_docs` 等，consumer 系列在用），**但劳动/时效/担保/租赁等
   领域没有接入**。

## §5 立项建议：扩展现有"场景 → 要件法条确定性补充通道"

**方案**：把 `domain_rules.py` 已验证的 consumer 模式扩展到缺口领域——按**法律领域知识**
（借款合同 → 民法典 667/675/676 + 诉讼时效 188/195；违法解除 → 劳动合同法 40/43/47/48/87；
标准工时 → 劳动法 36/44……）声明"场景 → 要件法条"映射，经现有 `scenario_supplement_docs`
通道**确定性**注入证据，使 writer 必有原料。

**为什么走这条路而不是改 writer**：WRITER_MISS = 0 ⇒ 改 writer（提示词/渲染）**无可改进**；
且 writer 的 system prompt 在**冻结物** `prompts.py` 里，改它要动冻结物。

### ⚠️ 最重要的红线：不得过拟合评测

`required_laws` 来自**冻结题集**（评测口径）。若映射表照着题集的 required_laws 抄，
就是**把代理目标当目标（评测过拟合）**——分数线会涨，生产能力没涨。
因此立项必须约束：
1. 映射依据 = **法律领域知识**（与题集独立来源：法条体系本身），每条映射注明依据；
2. 验收除题集外，**必须加留出题**（题集外的新 case）验证泛化；
3. 映射进 `domain_rules.py`（CONTRIBUTING 钦定的单一真源），**不散落**。

## §6 验收设计（预登记草案）

- 主判据：required-law HIT 率（本轮基线 **18/57 = 32%**）显著上升；**留出题**上同样上升。
- 守卫判据：全量 924+ 测试 0 failed；三道门禁绿；错误码分布不恶化（不得用"硬塞引用"换来
  `NON_CANONICAL_CITATION`/`UNSUPPORTED_NUMERIC_TOKEN` 上升）；冻结物漂移 0。
- 反过拟合判据：留出题 HIT 率 ≥ 题集 HIT 率 − 10pp（否则判过拟合）。
- 付费成本：1 轮全量验证轮（~7 分钟）+ 1 轮留出题轮。
