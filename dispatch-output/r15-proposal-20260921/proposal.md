## 0. 一个改变立项形态的事实（本次新核验）

**KB 现状（只读实测）**：99 个源里民事领域只有 **《民法典》1260 条**；
**没有《民法总则》**，也没有《合同法》《物权法》《侵权责任法》等 2021-01-01 被废止的九法。

⇒ **R15-3 的修复前提不成立**：就算把"知识快照日 / 适用区间"的数据模型拆开、检索允许按历史区间取，
**库里也没有《民法总则》可取**。⇒ R15-3 的正确立项形态是**数据先行**（先导入历史版本 + 效力元数据），
再谈检索模型——与 T7 补采同族（数据先行、代码后行），但规模大一个量级。

（另一个推论：R15-1 说的"模型正确引用了《民法总则》"这种**正确答案**，在当前语料下**不可能被生成**
——旧法条文根本不在证据池里。所以当前真实暴露面是 R15-1/R15-2 的**误拦**（把能答对的拦成 FAIL_SAFE），
而不是"答错没被拦"。这决定了修复的优先级取向：**先消误拦，再扩能力**。）

## 2. 建议的立项切分（四张票 + 一个前置）

### 票 R15-A · 低成本先扫雷（R15-5 + R15-4）
- R15-5：`_DATE_RE` 补 ISO 与斜杠两种**明确格式**（票面明确反对上通用日期解析器）+ 契约测试
  （支持/不支持的输入形状各列一张表）。顺带让 R15-2 的日期输入变好。
- R15-4：快车道按**确定性句段拆分**后逐段应用同一判据（**不加第二套版本门**）。
- 判据：先红（R15-5 用 ISO 日期反例、R15-4 用混合段落反例——报告里现成的动态复现）+ 全量变异。
- 工作量：小。**建议先做**：它消的是"该拦没拦"（漏判），与 B 消的"不该拦乱拦"方向相反、互不阻塞。

### 票 R15-B · 过触发校正（R15-1）——**需要你先认可一件事**
- 修复方向（票面已给）：区分 claim 实际引用的法律版本 + 是否含衔接说明；判不了 ⇒ 「不确定/需核验」，
  **不得仅凭两个日期判错**。无需模型判定器（确定性实现）。
- ⚠️ **前置**：`backend/tests/test_r15_version_tripwire.py:32-33` 把**当前的过触发行为锁成了正确结果**
  ⇒ 修 R15-1 必然要**改测试期望**。这等于承认"现有判据语义是错的"——票面已论证（需求样本只把
  「对 2019 事实直接按民法典答且不衔接」列为 critical，现实现扩大成"任何跨日期时效陈述都冲突"），
  但需要你点头这个**语义修订**。
- 附带收益：消除 fail-closed 的误拦 ⇒ 少出 FAIL_SAFE、少加注记、少禁缓存（直接改善成本与体验）。

### 票 R15-C · R15-3，**拆成两步**
- **C-0（前置调查，只读，可先做）**：历史法版本盘点——哪些被废止法律需要入库（民法总则/合同法/
  物权法/侵权责任法…）、它们的效力起止元数据从哪来、`data/laws_clean/` 的导入管线是否支持
  "已废止"状态。**本次已实测第一步：库里没有民法总则。**
- **C-1（数据导入）**：Owner 决策（规模大；与 T7 补采同族但需要法条来源与效力区间元数据）。
- **C-2（模型拆分）**：`context.law_as_of` 拆成「知识快照日」+「适用区间」；检索/工具按适用区间取
  历史版本；**保持证据来源、效力起止、引用校验机制不变**（票面明令不另建检索框架）。
  同时了结 ADR-018 已知残留④（快车道检索 cutoff 不随 `law_as_of` 变）。
- ⚠️ C-2 动 `agent/` 的 context 模型 + `retrieval.py` + `main.py` ⇒ 三票以来最大的一次生产码动作，
  必须等 A/B 落地、绿证重取之后再开。

### 票 R15-D · R15-2 有类型起算事件
- 「让调用方提供有类型的起算/权利受损事件」⇒ 依赖 writer/verifier 链路产出**结构化事实**
  （这是 agent 协议层的改动），且缺该事实时要"追问或保守标注"。**设计先行**（先出设计稿评审再动手），
  排在 A/B/C 之后。

## 补充（2026-09-21 04:4x）：R15-C-0 只读盘点结论 —— **建议 R15-C-1 暂不立项**

| 检查项 | 实测读数 |
|---|---|
| `backend/data/laws_clean/` | **0 个文件**（法条源文本目录为空） |
| KB `status` 分布 | **100%「现行」**（10266 / 10266，**零条已废止**） |
| KB `effective_from` / `effective_to` | **100% 为空**（完全没有效力期间元数据） |

**结论**：R15-3（跨版本案件取旧法证据）要落地，必须同时补三样东西：
1. **历史法文本**（《民法总则》《合同法》《物权法》《侵权责任法》《担保法》等被废止法律）——
   仓内**没有**，需外部权威来源；
2. **`status=已废止` 条目**——schema 有字段，但当前 100% 是「现行」；
3. **`effective_from` / `effective_to`**——字段存在但全空 ⇒ 导入管线必须改造后才能填。

⇒ 这是**项目级事项且带外部依赖**（法条文本从哪来、谁验收权威性），不是一张能在本仓闭环的票。
**建议**：R15-C-1（数据导入）**暂不立项**，登记为 blocked-by-external-data；
R15-C-2（知识快照日 / 适用区间拆分）在数据到位前做是空中楼阁，**一并延后**。
若将来拿到历史法文本，先做「导入 + 效力元数据」这一票，再谈模型拆分。

**另一条相关事实**：正因为 100% 是「现行」且无效力区间，当前 `law_as_of` 的 cutoff
在检索层**没有可过滤的对象**（`is_valid_by_time` 对所有条目恒真）⇒ 这也解释了为什么
票 I-2(a) 的护栏必须靠语料基准日而不是检索 cutoff 来兜。
