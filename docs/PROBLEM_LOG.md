## 一、合同评估（ADR-015，一期 + 二期，2026-08-06）

### 1. 骨架"法条供给弱"（eval 基线最大缺口）
- **问题**：eval 基线暴露报告引用的条文**一半不在骨架命中集**（cite_supported 0.5）。根因：`contract_clause_supplements.json` 映射覆盖不全——试用期/借款利息/格式条款措辞（"最终解释权""概不退款"）/免责/转租等常见陷阱没配条文，报告被迫靠 LLM 内部法律知识补（有"建议核对"标注，仍有错条风险）。
- **优化**：映射键 14→28 个（试用期→劳动19/20/21、最终解释权→民496-498+消保26、概不→506/497+消保26、转租→715/716、瑕疵→612/613/617、没收→585、经济补偿→劳动46/47/87、保修→承揽770/781、质量问题→610、无条件→543、专项培训→劳动22、中介→961、最终解释→496-498、主张任何权利→506 等），全部精确直查验证在库。
- **结果**：cite_supported **0.5 → 0.95 → 1.0**（11 份考卷）。
- **判断指标**：`cite_supported` = 报告引用条文 ∈ 骨架命中集的比例（eval 基线，确定性 verifier 零 LLM）。

### 2. 风险词表中性词误报（rubric 虚高 / coverage 虚低）
- **问题**：风险关键词把"解除/赔偿"等中性词当风险点——正常解除权/责任条款被标记，rubric 虚高（劳动合同被判"高"）、coverage 虚低（低风险条款算"应覆盖"漏报）。
- **优化**：移除"解除""赔偿"两个中性词。
- **结果**：C2 劳动合同 rubric 高→中（与报告一致）；coverage 0.90→1.0。
- **判断指标**：`level_match`（报告等级 vs rubric 确定性等级）、`coverage`（风险条款覆盖率）。

### 3. 合同续聊被通用 clarify 拦截（会话连续性 bug）
- **问题**：合同续聊第二轮正常、第三轮短句（"那利息按24%算吗"）被分支0.5 通用 clarify 判"信息不足"返回通用反问，**绕开合同路径**。根因：通用 clarify 闸在合同分支（0.3）之前执行。
- **优化**：`pre["contract_data"]` 存在时 `strategy` 强制 direct（信息确认闸由合同分支 `need_clarify` 负责）。
- **结果**：三轮续聊（贴合同→问违约金→问利息）全走合同路径。
- **判断指标**：端到端多轮追问——第二轮/第三轮是否输出合同报告而非通用反问。

### 4. 保修条款兜底召回错配担保条文（C9）
- **问题**：装修合同保修条款未命中映射 → 兜底语义检索召回**担保合同**条文（686-693），驴唇不对马嘴（报告自行指出错位）。
- **优化**：补"保修"键 → 承揽 770/781。
- **结果**：报告改引承揽条文；`unsup` 列表清空。
- **判断指标**：`unsup`（报告条文 ∈ 命中集之外的，即骨架漏供给）。

### 5. 保修"根治"未达——担保子串误命中
- **问题**：code-review 实测"承担**保**修"含子串"**担**保"（担+保相连）→ "担保"键仍命中 686/687/693 进命中集，修复 #4 只加键没去掉错误条文。
- **优化**：`contract_supplement_docs` 排除 `kw=="担保" and "保修" in clause_text`。
- **结果**：保修条款只命中承揽 770/781，担保条文清零。
- **判断指标**：`contract_supplement_docs` 返回命中条文集合（确定性直查）。

### 6. 图片合同续聊断裂（转写全文未进续聊上下文）
- **问题**：图片合同的转写全文存于 `Message.image_desc`，续聊拼 prev 只找 `content`（用户请求词"帮我审这份合同"）→ 拼不回全文 → 落"请补充合同全文"反问。
- **优化**：续聊找到上轮合同消息时，若 `image_desc` 是合同转写则用它拼回全文。
- **结果**：图片合同续聊贯通（竞业补偿分析引劳动法）。
- **判断指标**：端到端多轮追问（审图 → 追问走合同路径）。

### 7. 仅传图续聊断裂（content 为"[图片]"）
- **问题**：code-review 发现 #6 只修一半——用户**只拍图不写字**时 content=`[图片]`，续聊闸 `is_contract_review(content)` 判 False → 转写全文仍拼不回。
- **优化**：`content=="[图片]"` 且 `image_desc` 是合同转写也视为合同消息。
- **结果**：仅传图续聊贯通。
- **判断指标**：端到端（content 为空/仅图片 → 追问走合同路径）。

### 8. 截断信号下游丢失
- **问题**：文件端点截到**恰 12000** → `build_contract_data` 判 `len>limit` 为 False → `truncated=False` → 报告缺"未覆盖条款段"尾注、`analysis_runs` 不记录。与直接粘贴超长行为不一致。
- **优化**：`ChatIn` 加 `truncated` 字段，前端上传截断时穿透，`_pre` 合并进 `contract_data`。
- **结果**：截断合同报告含"未覆盖条款段"尾注，analysis_runs 记录准确。
- **判断指标**：截断合同（>12000 字）报告是否含"未覆盖"尾注。

### 9. 图片识别合同（能力从无到有）
- **问题**：`describe_image` 只有"不超过150字"摘要——合同图片被压成摘要，**无法**切条款做评估。
- **优化**：自我路由 prompt——合同/文书图片逐字转写全文，普通图片才 150 字摘要；明确禁止模型加评论。
- **结果**：多模态转写锚点命中 **94%**（六条关键信息全中）；端到端 4 场景验收通过（劳动合同/借款/非合同图不误触/续聊）。
- **判断指标**：转写锚点命中率（原文 5 字片段 ∈ 转写比例）；端到端场景断言。

### 10. 确定性 verifier 自身缺陷（eval 基建）
- **问题**：verifier 三处不鲁棒——①`structure_score` label 全命中但 `|` 字段少时提前返回 0.5（C1 结构误报 0.38）；②`_LEVEL_RE` 被 markdown 加粗 `**高**` 干扰 → 等级提取 none；③`fabricated_fragments` 把改写/修改建议当编造（44 处"疑似"）。
- **优化**：①label 全命中优先判满；②等级正则容忍 markdown/引号；③人工复核确认为**误报**（一期实际零编造，非缺陷）。
- **结果**：structure 回到 1.0、等级提取正确、确认无编造。
- **判断指标**：verifier 单测（16→20 例）+ 报告人工复核。

## 二、早期质量基线（ADR-012/014，法考题评测）

### qa_cache 污染（真实基线测量障碍）
- **问题**：judge 基线答案来自预生成语料（`tier=qa_cache`），**从未走真实 LLM** → multi_ok 数字失真（0.43/0.57/0.64 全不可信）。
- **优化**：`/api/chat` 加 `no_cache` 参数绕过 QA/答案缓存。
- **结果**：真实基线 **0.5714**（8/14）。
- **判断指标**：multi_ok、cite_ok（eval 脚本 `no_cache=True` 实测）。

### multi_ok 子集判定 bug
- **问题**：`true_letters <= declared` 只查**不漏选**，误选假项也算对 → 基准被高估。
- **优化**：改为 `declared == true_letters`（恰好列出全部正确项）。
- **结果**：判定精确。
- **判断指标**：multi_ok 单测（8 例，含全选/超集/漏选边界）。

### _EXAM_VERDICT_RULE 被 SYSTEM_BASE 压制
- **问题**：真伪判定规则在提示词**尾部**被 SYSTEM_BASE 压制无效 + 规则模糊。
- **优化**：重写为真伪判定五条 + 位置前移到 OUTPUT_FORMAT 之前 + 归因修复（context_block 显式声明）。
- **结果**：id5/id16 转正；multi_ok 真实基线 **0.64→0.71**。
- **判断指标**：multi_ok（no_cache 重跑对比）。

### contract_split 丢首段（结构性漏条款）
- **问题**：diagnosing-bugs 发现条标前的引言/首段被丢弃——结构性漏条款。
- **优化**：保留为"前言"段 + 回归测试。
- **结果**：首段保留。
- **判断指标**：`contract_split` 单测（preamble 保留）。

### 短合同不触发
- **问题**：~120 字劳动合同不触发 contract_mode → 走普通检索跑偏到《国籍法》。
- **优化**：`_MIN_CONTRACT_LEN` 150→80。
- **结果**：短合同正确触发（~100 字含 2+ 合同名词触发）。
- **判断指标**：`is_contract_review` 单测（短合同触发 / 口语短句不触发）。

## 四、前端体验整改（2026-08-06）

### 1. 聊天页客户端异常（Application error）
- **问题**：登录后进聊天页整页报「Application error: a client-side exception」。根因：新增的法条卡 `useLayoutEffect` 被放在 `if (loading || !user) return null;` **之后**——未认证渲染提前 return 不调用该 hook，认证通过后继续渲染才调用 → 违反 Hooks 规则 → React 抛「Rendered more hooks than during the previous render」。
- **优化**：`useLayoutEffect` 上移到提前 return 之前（与其余 hooks 同层），并加注释警示。
- **结果**：无头 Edge 注入 token 认证加载 /chat：完整渲染、**客户端异常数 0**（commit 559ff3a）。
- **判断指标**：认证后 /chat 是否报错；无头 CDP `Runtime.exceptionThrown` 计数。

### 2. 法条标注漏"省略书名号的连续条号"
- **问题**：「《民法典》第四百九十七条、第五百六十三条」只有第一处标色弹卡——`annotate` 只认完整「《X》第N条」，第二处无前缀不标不弹。
- **优化**：单正则 alternation 一次从左到右处理，独立「第N条」归入同段最近《X》，`.law-ref` 输出 `data-source`；弹卡读取 `data-source`。
- **结果**：省略书名号的条号同样标色、hover 弹卡（commit 04f7f24）。
- **判断指标**：该句式两端都 `.law-ref`、hover 都弹卡。

### 3. PC 语音识别质量差（Web Speech）
- **问题**：浏览器 Web Speech 转写不准（用户实测不满意）。
- **优化**：改走后端 Qwen livetranslate 语音模型转写（门禁实测：OpenAI 兼容 `input_audio` + `translation_options` + stream，真实人声逐字转写正确）；新端点 `POST /api/chat/transcribe`（限流 20/min、≤10MB、白名单格式）；前端 PCM→WAV 录音（`recorder.ts`，零增益防回声）；失败/无麦克风回退 Web Speech。
- **结果**：端到端 curl 200 转写原文一致；401/400 分支正确；门禁脚本 `scripts/smoke_transcribe.py` 可复现通过（commit 04f7f24）。
- **判断指标**：`smoke_transcribe.py` 任一 wav 变体返回非空文本；端到端转写文本与录音一致。

### 4. 法条悬浮卡闪烁 / 乱飘
- **问题**：hover 一会儿显示一会儿消失（每次 pointerover 都发请求、移向卡片即关）；`fixed`+视口坐标不随滚动 → 卡片乱飘；窄屏 320px 溢出。
- **优化**：浮层改 `absolute` 锚定滚动容器（随内容滚动）；hover 150ms 进入延迟 + 300ms 离开宽限（ref 与浮层同组）；`lawCache` 同条文只请求一次 + 请求序号防乱序；下方空间不足自动翻到上方；宽度 `min(20rem, 容器宽)`；玻璃卡质感。
- **结果**：hover 稳定、滚动跟随、上下自适应（commit 04f7f24）。
- **判断指标**：hover 150ms 出现且不闪断；滚动时卡片跟随 ref；近底部自动翻上。

### 5. 移动端"全部挤成一团"
- **问题**：移动端布局崩，全挤一团。
- **优化**：`h-screen→.app-shell`（100vh/100dvh 兜底 + overflow-x clip）；场景卡 `grid-cols-1 min-[400px]:grid-cols-2`；flex 子项 `min-w-0`；AI 气泡 `overflow-wrap:anywhere`；侧栏 `max-w-[85vw]`；弹层窄屏自适应。
- **结果**：375px 无横向滚动、无挤压（commit 04f7f24）。
- **判断指标**：DevTools 375/768/桌面三档无横向滚动条、布局不破。

### 6. 主题不统一 / 颜色分层明显 / 撞色不足
- **问题**：对话侧栏会话记录还是旧灰白风格；整体颜色分层明显、不够"撞"。
- **优化**：撞色加深（`--ink #23314f`/`--accent #f2547c`/`--sea #3d9be9`/`--slate #5c7090`）；侧栏会话项 accent 主题化；标注四色（法条/时效/金额/倍数）全走变量；全站玻璃卡（admin 侧栏与面板、LawCard、login/admin 错误框变量化）；消息头像改主题粉。
- **结果**：全站色板统一、撞色对比增强（commit 04f7f24）。
- **判断指标**：浏览器视觉验收。

### 7. agent 回答出现 `*` / `-` 符号
- **问题**：回答含 markdown 列表/强调符号，不美观。
- **优化**：`OUTPUT_FORMAT_RULE` 禁 `*`/`-`/`#`/反引号等排版符号，改用「一、二、三」「1. 2.」「①」；前端 `stripMarkdown` 对完成态再清一道（行首 `- ` → `· `，移除 `*`，保留 3-5 中缀连字符）。
- **结果**：双保险，回答不再出现 `*`/`-`（commit 04f7f24）。
- **判断指标**：随机长回答无行首 `*`/`-` 残留（SSE 完成态一次清理）。

### 8. 无法删除历史对话
- **问题**：侧栏会话不可删除。
- **优化**：侧栏项 hover 显示 ✕ → confirm → `convApi.remove`（后端 DELETE 端点已存在）→ 刷新列表；删除当前会话清空消息区。
- **结果**：删除会话功能落地（commit 04f7f24）。
- **判断指标**：删除后列表刷新、当前会话清空。

## 附录：判断指标口径（确定性 verifier，零 LLM）

| 指标 | 含义 |
|---|---|
| `trigger_ok` | is_contract_review 触发判定正确率 |
| `coverage` | 风险条款（确定性打标）被报告覆盖比例——抓"漏条款" |
| `cite_supported` | 报告引用条文 ∈ 骨架命中集比例——抓"引对条" |
| `fab_count` | 报告引号摘录不在合同（疑似编造，需人工复核） |
| `structure_avg` | R_n 五要素（位置/严重度/原文/法条/建议）完整度 |
| `level_match` | 报告结论等级 vs rubric 确定性等级（match/相邻/夸大） |
| 转写锚点命中率 | 图片转写质量（原文 5 字片段 ∈ 转写比例） |
| 全量 pytest | 回归防线（当前 319 passed） |
