## 四、痛点：为什么这是个"两难"

### 4.1 继续采集的边际收益已经为零

```
8 代 440 次真实调用（004/005=20题、006-011=30题 × 双模式）→ 结论从未反转（Agent ≤ RAG）
每一代新候选的成本：镜像构建 + 30×2 采集（~1.5h）+ 绑定/审计/门禁（~1h）
```
从 005 的 −0.083 到 008 的 −0.042，口径每代"合理化"一次，差距单调收窄但**方向从未反转**。008 终局把结论写死为"质量优势未获证实"。010/011 修复的是评估公平与引用精度，**不是 Agent 能力本身**——继续采集无法创造新信息。

### 4.2 三个方向各自的痛

| 方向 | 解决了什么 | 痛点/代价 |
|---|---|---|
| **a) 修评估口径** | 反问题 0/0 记 1.0、逐字匹配过严等"公式 vs 题集"矛盾 | 改评估器=动摇 8 代可比性；需预注册+数据所有者批准；修完可能仍是"容差内持平"而非反超 |
| **b) 改路由计分** | Agent 只在其被设计的复杂题上被评价 | 等于是改"被测对象"定义——**变相承认 Agent 不适合全题集竞争**；破坏与 RAG 的直接可比性 |
| **c) 接受现状** | 不再为"质量分数"纠结 | 需你认可：**Agent 的核心价值 = 复杂题的安全护栏 + 诚实交互**，不是 top-1 质量 |

### 4.3 最尖锐的痛点（一句话）

> **评估体系要求"Agent 质量 ≥ RAG"才放行，但 8 代数据显示 Agent 的差异化价值根本不在"质量更高"，而在"高风险场景更安全"。用质量指标给安全件设门槛，是尺子量错了东西。**

## 五、推荐：接受现状（c）为默认解

**推荐理由**（按证据强度排序）：

1. **数据一致性**：8 代 440 次调用，方向从未反转——继续采集违背"诚实标注、不凑数"纪律。
2. **价值真实**：Agent 的安全全零 + 诚实反问 + 确定性路由，是**已被独立层（judge/人评同源 96% 一致）验证**的真实资产，不是营销话术。
3. **红利可得**：009 已 `allowed=true`（v2 容差内持平）；010/011 把引用精度与记法公平修完。选 c 即可把全部成果直接推到"灰度就绪"，无需再开新候选。
4. **顺带解 ①②**：c 通过后，灰度上线（①）与恢复独立审计（②）就都进入"可执行"而非"待决"。

**落地方式（选 c 后的动作）**：
- 在产品定位文档中正式声明：「Agent V1 定位 = 复杂/高风险法律咨询的**安全增强件**（诚实反问 + 安全全零），不承诺质量超越 RAG」；
- 发布口径写入 `docs/runbooks/deployment-v1.md`（灰度阶段 Agent 仍 `AGENT_ENABLED=false`，按 route 逐步放量）；
- 009 的 `allowed=true` + 010/011 修复成果作为候选基线，等 ① 环境 + ② 审计就绪后进入灰度。
