## 1. 一句话结论

**别用正文正则取 `effective_from`。** 99 部法里按"文末那条'本法自……起施行'"能取到唯一日期的有 88 部，
但其中 **36 部（占现网碎片 34.6%）取到的那个日期早于本版公布日 —— 它是原法的施行日，不是本版的**。
这条路一旦自动化，就是把 3549 条碎片的时效轴整体往前挪几十年，而且**不会有任何测试变红**。
这正是语料数据票 §2 警告的"看着补了语料、实际口径全错"那一类，只是这次错得更安静。

## 4. 这一条不是推断，是独立核过的

元典检索 `专利法(2020修正)`：`publication_date = 2020-10-17`、**`effective_date = 2021-06-01`**、
文号 主席令第55号（`id 4c90a01a66d7c6ae…`）。而 `data/laws_clean/中华人民共和国专利法_20201017.txt`
正文末条是「第八十二条　本法自1985年4月1日起施行。」（`id` 另一条 2020 修改决定 `ff0dd604…` 同为 2021-06-01）。
⇒ 三个事实对齐：**修正后的合文本，文末施行条款保留的是原法施行日**；本版的施行日在主文本之外（主席令/修改决定）。

## 5. 因此 E7 的执行形状（建议，尚未开票实施）

1. **主源换成元典结构化字段**：`yuandian_search_laws_and_regulations` 按 `regulation_name` +
   `primary_effect_level=法律` 取 `publication_date` / `effective_date` / `validity_status` / `document_number`，
   99 部一次一部，逐条留 `id` 作溯源（数据票 §3-F 的溯源键在这里正好落地）。
2. **正文正则降级为交叉校验**：只允许它"报警"，不允许它"填值"——
   即 `文末日期 != 元典 effective_date` ⇒ 记一条待人工确认，而不是取任一边自动写入。
   按本盘点，这道校验会命中 36+4=40 部（约 4238 条碎片），**这就是它的价值量级**。
3. **写侧加一条方向不变量**（并进 T3 第④口）：`effective_from < promulgated_at` ⇒ 整批不出。
   法律一般不可能在公布之前施行；这一条正是本盘点里 36 部的探测器，成本一行。
   ⚠️ 若遇"公布日与施行日同日"（PUB 档 7 部）按 `==` 放行，不许写成严格大于。
4. `status` 与 `effective_to` 仍按已签口径逐条判（元典 `validity_status` 到本仓字面值的映射**尚未签字**，
   见数据票 §3-A"部分失效/尚未生效"那一格）⇒ E7 只能先补 `effective_from`/`promulgated_at`，
   **不要顺手动 status**。

## 6. 复算方法

分类器是临时一次性脚本（本轮未入库，避免留一份"能跑但没人维护"的正则）；复现要点：
`data/laws_clean/*.txt` 共 99 个文件（文件名后缀=本版**公布日**，非施行日）；短名规则同
`scripts/import_docs.py:short_source`（去 `中华人民共和国` 前缀 + 去 `_YYYYMMDD`）——
⚠️ 本盘点第一版就是把短名少去了日期后缀，导致 99 部对库全部 miss、碎片数报成 0，
所以**分桶与库内 source 的交集必须显式打印"命中数合计 == 10266"** 才算数（本次已对齐）。
