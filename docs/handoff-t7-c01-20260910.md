## 5. C01 缺陷：根因、修复与一个重要的过程教训

### 5.1 缺陷现场

probe-15（付费探针）跑 C01 得到：`agent_completed=False`、`final_chars=0`、`errors=['EVIDENCE_COVERAGE_DEFICIENT']`、status=failed；`clarifications=2/2`（澄清预算耗尽）、`tool_calls=3/10`（预算充裕却未补检索）、**issues=4 但只检索了 3 个**。

> **⚠️ 重要限定（本次审核发现）**：**C01 的失败面在不同轮次并不一致。** 本次审核从 run-12 的 checkpoint 实测到：**同一题 C01 在 run-12 里死于 `GENERATOR_FAILURE`**（见 §6.8），而非这里的 `EVIDENCE_COVERAGE_DEFICIENT`。
> ⇒ 本节的根因与 §5.3 的修复，**只覆盖"issue 漏检 → EVIDENCE_COVERAGE_DEFICIENT"这一条路径**；`GENERATOR_FAILURE`（writer 生成本身失败）**是另一条独立线路，本次未处理**。
> ⇒ 判定修复是否有效时，**必须以 `EVIDENCE_COVERAGE_DEFICIENT` 是否消失为准**；若 C01 仍报 `GENERATOR_FAILURE`，那不构成本修复失败的证据。

### 5.2 根因（实证复现，非推测）

`backend/agent/controller.py` 的 `_handle_evaluation` → `MISSING_FACT` 分支里，`CLARIFY_BUDGET_EXHAUSTED` 时**无条件转 DRAFTING，不检查是否还有 issue 从未检索**。配合 `_seed_issue_retrievals` 的扇出"每轮只推进一步就被 return 打断"，**澄清轮次 = 可推进 issue 数**。

⇒ **当 `issue 数 > 澄清预算 + 1` 时，尾部 issue 必然漏检** → 进 DRAFTING 时该 issue 无证据绑定 → verifier 判 `EVIDENCE_COVERAGE_DEFICIENT` → 回喂被（正确地）拒绝（writer 造不出未检索过的法条）→ 整轮 failed、用户拿到空终稿。

**复现通路**（可复用）：真实 SQLAlchemy store + `execute_agent_request` + `resume_with_user_fact` + `_DEFAULT_RUN_LOCKS` 组成时序循环（run → resume → run…）。复现结果与真实现场完全同构。

### 5.3 修复（v2，采纳版）

新增终止条件 `AgentController._every_issue_retrieval_attempted(state)`（`backend/agent/controller.py` 约 703 行），在 `_handle_evaluation` 的该分支用它判定：**"每个缺证据的 issue 是否已发起过 `retrieve_laws`"**（查 `state.action_fingerprints`），而非"是否已拿到证据"。

- 语义依据：扇出与判定两处构造指纹的参数**完全一致**（`RetrieveLawsInput(query=issue.question, k=4)`），一旦试过，重试必命中 duplicate 守卫、不可能产生新证据 → 补齐到头，**fall through 到原有确定性收敛路径**，而不是回 PLANNING。
- 转移处保留**幂等短路**（已是 PLANNING 则不再 `transition`，防 `InvalidTransition(planning→planning)`）。

### 5.4 ⚠️ 过程教训（务必内化，这是本次最贵的经验）

**第一版修复（v1）是错的，而且它通过了测试。** v1 用 `_every_issue_has_evidence` 当循环条件——该函数在检索器**持续空命中**时恒为 False，于是**无界重入**：实测跑到 **10,750+ 次仍未停，最终段错误崩溃**（栈耗尽于 SQLAlchemy 查询编译）。

更阴的是我一开始报的数字是**假的**：我用带 `if n > 300: raise` 阈值的探针测量，异常被 `service.py:345` 的**裸 `except Exception`** 吞成通用 `AGENT_EXECUTION_FAILURE`，于是「无界」被伪装成「有界失败（297 次后结束）」。**把阈值提高一个量级重跑**才暴露真相。

**三条可迁移的纪律**：
1. **循环条件必须写"是否已尝试"，不能写"是否已达成"**——后者在外部依赖无产出时天然无界。
2. **补检索/重试类逻辑的收敛性，必须在"外部依赖持续返回空"的边界场景实测**，正常场景永远看不出问题。
3. **带自设上限的探针必须报告"是否撞到自己的阈值"**；看到"循环 N 次后失败"，先怀疑 N 是自设上限。

## 7. 语义防误伤清单（避免误读）

- **"run-N"**：一次在线验证轮（Gate2 评测器跑 frozen-cases）。**不同 run 对应不同代码状态，不可互易**。run-9=G1、run-10=方案A、run-11=G2。
- **"PLANNER_PARSE_ERROR"**：Planner 输出无法解析为 PlanDecision（L1 死亡点）。
- **"EVIDENCE_COVERAGE_DEFICIENT"**：verifier 判某 issue 的 claim 未绑定有效成文法证据。**这是"writer 没引用"，不是"没检索到"**——检索到了 ≠ writer 正确引用。
- **"ISSUE_DECOMPOSITION_INVALID"**：分解阶段校验失败，**发生在 create_run 之前，DB 无 agent_run 记录**，只有服务日志 `agent_pre_run_failure`（C07 的 conv_id=null 即此）。
- **"GENERATOR_FAILURE"**：Writer 生成本身失败（非 verifier 拒绝）。
- **"full_closure"**：两层 judge（机械 + 法律域语义）全通过题数 / 分母。
- **"方案 A" = "G6"**：同一件事——planner 用 `response_format=json_schema` 强制结构化。
- **"frozen-\*"**：冻结物。**任何助手不得修改**；要改需 Owner 下新决策书。
- **"AGENT_ENABLED=true"**：必须带在启动环境里，漏设会静默走 RAG 路径、run 数据作废。
- **"probe-N"**：付费探针轮（小规模、单题或少数题），与正式 run 区分。

## 8. 🚨 本机沙箱环境踩坑（**无记忆接手必读**，否则会白烧很多轮）

这些是本机（Windows + WorkBuddy 沙箱）特有的坑，与项目代码无关，但会直接毁掉你的诊断结论：

1. **Bash 工具默认 120s 超时会截断长任务**。`gate2_runner` 单题耗时 60–120s+（含 LongCat 外呼），前台跑表现为"零输出 + exit 1 + SIGTERM"，**极易误判为进程被杀**。→ **一律用 `run_in_background=true`**（后台任务能稳定长跑，已验证）。
2. **`tasklist` / `wmic` / `schtasks` 被沙箱黑名单拦截**：`tasklist` 会显示零 python 进程（即使服务在跑）→ **不能用于判存活**。
3. **PowerShell 工具本机拿不到 stdout**（exit 0 但无输出，`Format-Table`/`Out-String` 无效）→ 读注册表用 Python `winreg`，看进程用 `subprocess tasklist`。
4. **PowerShell `Start-Process` 在本沙箱静默失效**（不报错、文件创建但进程不启动）→ 不能用来脱离会话启动长任务。
5. **验证手段只信文件系统**（产物/日志文件）。不信进程查询命令。
6. **`[safe-delete]` 沙箱会拦截 Python 删除**（`os.remove`/`shutil.rmtree` fail-closed）。正确解法（已实测）：子进程 env 设 `CODEBUDDY_SAFE_DELETE_ENABLED=0` **并**移除 `CODEBUDDY_SAFE_DELETE_SANDBOX`，再用原生删除。详见 `~/.workbuddy/memory/workbuddy-delete.md`。
7. **pytest 退出码不可信**：本机 safe-delete 钩子在 pytest 结束时会污染退出码为 1（点阵全过也报 1）。→ **用 `--junitxml` 取机器可读结果作确定性证据**，并用点阵计数交叉印证。
8. **含中文路径的 Python 脚本要加 `-u`**，否则崩溃时缓冲区丢失（exit 1 + 零输出）。
9. **内联 `python -c` 里出现 `$Recycle.Bin` 会被 bash 展开成 `.Bin`** → 涉及该路径必须写成 `.py` 文件。
10. **Python 脚本内发起联网请求（urllib/http）会让整个 bash 进程被杀**（exit 1、零输出）→ 需联网探测时改用 WebSearch/WebFetch 工具。
11. **`os.walk` 统计文件路径大小恒为 0** → 统计函数必须先 `os.path.isfile` 分支。

**付费与并发纪律**：LongCat 外呼极慢（单请求最高 ~960s 观测）；**共享数据库、服务端口、付费账户禁止并发**；一次开发轮只算候选证据。
