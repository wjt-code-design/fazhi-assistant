## 1. 问题定义（证据链，全部可溯源）

- **现象**：Agent 子查询（程序性问句如「起诉条件」「立案材料」）把**他域专属程序法**
  条文召回进证据池：行政诉讼法 49/50/51/52、刑事诉讼法 101/103/113/180 出现在纯民事案。
- **证据**：
  - `evals/probe-results.json`：E01 forbidden 混入 2/2、E02 混入 3/6（子查询轨，池内余弦精排路径）
  - t5（2026-09-13）：C07 终稿实际引用了《行政诉讼法》49/51（混入穿过证据池到达终稿的唯一实锤）
  - 基线 v2：E01-E05 带禁引判据的 12 条无一到达终稿（因全部未产出终稿——样本不足，
    不构成「缺陷无害」证明）
- **风险定位**：证据池污染 → writer 引用绑定合规但法律适用性错误（确定性校验无法拦截
  「引用存在于绑定证据」的错误适用），即 t5 报告的结构性缺口。

## 2. 方案 R1：程序法家族隔离（检索层后过滤）

**规则**（模拟脚本 `evals/simulate_filter_r1.py`，数据 `evals/filter-simulation-r1.json`）：

- 程序法域表（静态、代码内常量，不改知识库）：
  `民事诉讼法↔civil，刑事诉讼法↔criminal，行政诉讼法/行政复议法↔administrative，
  海事诉讼特别程序法↔special-maritime`
- 判域输入：本次检索 query 文本（Agent 逐争点检索时=issue 问句）+ 案例域元信息（若可得）。
  指示词表：criminal（刑事/诈骗/报警/判刑/犯罪）、administrative（行政/政府/处罚/罚款/听证）、
  civil（民事/借款/买卖/劳动/合同/消费/赔偿/时效/起诉）。
- **多指示词冲突或零指示 → mixed → 不过滤（行为与现状完全一致，保守优先）**。
- 判域明确时，仅剔除**他域专属程序法**条文；**实体法永不过滤**（民法典/刑法/劳动法等
  跨域适用是真实法律场景，如民刑分流案 C10——交给 writer/verifier，不在检索层拦截）。

**离线模拟结果（in-sample，探针 20 案例 × top-6=120 条）**：
```
forbidden 混入杀死 5/5，漏杀 0；required 误杀 0/19；噪声（非金标他域程序法）顺带清 3；
其余 112 条结果不变；18/20 案例零改动（mixed/无他域混入不触发）。
```
⚠️ 此为规则设计样本，**不构成有效性证明**——证明只认 §4 双集。

## 2b. 语义复核实证（2026-09-13 追加，界定 R1 边界）

- **C07（借款案）**：混入《民法典》694（保证期间条款，串章）+199（除斥期间）。
  均为实体法 → R1 不覆盖。

  纯实体法混入 → R1 不覆盖。

**结论（界定 R1 价值）**：R1 是必要的、非充分的——只修「检索层召回他域程序法」这一类。
实体法串台/灌水（C07/C09 型）与「生成期注入程序法」（C05 型）需**终稿后校验**兜底（见 R1b）。

## 2c. R1b：终稿后程序法校验（2026-09-13 追加，C05 实证驱动）

- 位置：Agent finalize 前（verify 后置钩子，最终稿引用清单上）。
- 规则：对终稿抽取的《法名》第X条引用清单，按与 R1 相同的判域表检查「他域专属程序法」
  条文出现在**非对应域终稿**中 → 判定 FAIL（非静默，写 FAIL 码走 fail-closed）。
- 判据：`agent_completed` 不受影响（是校验层结果，不阻断已完成状态）；新增独立度量
  `proc_misroute`（0/1），作为终稿质量红线。
- 与 R1 分工：R1 拦检索池、R1b 拦终稿引用——两者独立可回滚。

## 5. 已知风险与止损

1. **规则过拟合**：指示词表来自 20 例设计经验 → 留出集 P4/P5 不过 = 按纪律回退不接线，
   文档标注「规则形态证伪」，不追加指示词救数（追加=过拟合循环）。
2. **判域错误**：Agent issue 问句可能比案例题面更抽象（如「主体资格认定」无指示词）
   → mixed 兜底=不过滤，退化为现状，无害。
3. **空池效应**：若争点仅需程序法证据且被他域标签误标 → §3 空池可观测条款兜底，
   出现即 STOP 分析不误判 FAIL。

   云路径重跑 probe 对照（另行 ≤0.05 元）。
