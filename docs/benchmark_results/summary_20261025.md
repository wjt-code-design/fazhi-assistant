## 对「如何保证客观」的回答

1. **金标可追溯到构造**：题库由库内条文抽样 + 人工改写，`(法名, 条号)` 不经过模型。
2. **主指标是集合运算**：precision / leak / hallucination / recall 全部是条号集合的
   交并差，可复现、可审计、零模型参与。
3. **LLM 只在无机械结论时兜底**：`grounding_verdict()` 先看机械分类，
   只有「答案没引用任何条文」时才调用 judge，且 judge 固定 text 档 + temperature=0。
4. **能自动化的都自动化**：解析器缺陷、题库歧义都是被机械交叉校验抓出来的，
   不是靠 judge 打分发现的。

## 关于「借助插件/MCP 增强法律判断」的结论

**当前不可行，且方向本身有偏差。**

- 已装插件里没有中国法律权威数据源：context7 是技术文档、apifox 是接口文档、
  deep-research 是通用检索，都不能判「某条法条用得对不对」。
- 即使能联网检索法条，也只能做到「引用是否为真」——而这恰恰是现有机械核验
  （`citation_hallucination_rate`）已经做到且更可靠的事。
- 让 LLM 判「法律答案是否正确」被列入对抗性审查否决项：无权威法源可核、
  且与答题模型同源，等于自证。

因此本方案的口径是：**不判「法律对错」，只判「答案与给定条文的一致性」**，
并把可机械化的部分全部机械化。

## 仍存在的局限

- 解析器只认书名号引用：未加书名号的写法（如「刑法第四十六条」）不计入，可能低估引用总量。
- judge 仍是单一模型，题库 59 题，样本量不足以做小差异的显著性判断。
- 检索失败的根因（口语化提问无任何法律术语）已定位到 5 个具体样例，但查询改写尚未实施；
  clarify 门槛已定位并修复（`clarify.py` `_UNDERSPEC_RE`）。
