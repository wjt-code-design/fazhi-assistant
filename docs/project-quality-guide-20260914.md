### 任务 C：一次只修一个可证明的问题

从已有错误终稿开始，优先选择影响明确且证据完整的一例，并保留一个相近正确样本作回归对照。

每次开始前只写一小段：**问题、原因证据、最小修改、成功条件、停止条件**。不另建预注册文档体系。

1. 沿原始输入 → 分解后的事实/争点 → 实际检索结果 → writer 输入输出 → verifier/finalizer → 用户终稿定位错误首次出现的位置。
2. 能复用日志或数据库记录就复用；仅当缺少信息阻碍定位时补必要字段。日志避免记录密钥和完整用户文本。
3. 先证明失败，再做最小修复。确定性 bug 的测试期望来自独立样例，不复制实现算法；环境错误不算有效红灯。
4. 离线不能回答的问题才进行真实模型小样本验证，先验证目标样本，再决定是否扩展。
5. 效果不成立，撤销自己此次尝试或保持实验关闭；不要还原其他人的文件，不覆盖旧证据。

同类真实生成失败连续两轮，停止该假设的扩样并分析；同一 bug 连修三次仍无法解释，停止继续补丁。停止的是当前无效尝试，其他独立任务可以继续。

完成标准：目标问题得到直接证据支持的改善、关键对照无新增错误、相关回归通过。小样本只能证明本次观察，不能承诺普遍准确率。无明确可修问题时结束工作，不为了“优化”继续加代码。

## 4. 质量优化优先级与验收标准

优先顺序：**关键法律适用错误、无依据结论和争点遗漏 → 检索召回与回答完成率 → 格式、篇幅、速度及代码简洁度**。格式已经导致误解时提前处理。

### 4.1 检索质量

- 检查关键依据是否召回、是否适用于案情和时间、是否混入不适用法条。法条在库不证明其有效或适用。
- 用实际 Agent 子查询及实际精排路径复现。独立探针的 top-k 与真实证据池不同，不能据探针推断模型“绕过证据池编造”。
- 固定对照中除目标变量外的案例、k、索引版本和检索路径；若本次就是调整 k 或精排路径，明确其为唯一目标变量。云精排与本地降级分别标记，不把意外切换当成同一条件。
- 先判断缺口在源数据、切分、query、排序还是过滤，再改对应位置；不默认扩大 k、注入更多法条或堆关键词。
- 必要依据命中数/已审核必要依据数，可用于观察召回；不适用结果数/已审核返回结果数，可用于观察噪声。按法名、条号和适用版本去重，避免重复 chunk 虚增命中。分别报告分子分母及判定来源，不笼统合成“检索准确率”；分母为零记不可测。金标不完整时标注局限。
- 引用原文和有效性核实优先权威来源；记录来源与适用时间，不凭生成模型建立法律金标，不擅自改写知识库条文。

R1 继续关闭，全称法名漏过滤登记为重新启用前必修；不专门投入修复已停止方案。原问题拼入判域文本仅为待验证假设，不能预先承诺解决 mixed 场景；优先离线反例验证，不扩建领域分类器。

### 4.2 生成质量

本次选入验收的每份终稿按以下问题审核，任一关键法律适用错误都不能被其他指标抵消。这是样本验收标准，不要求新增逐条人工审批的线上流程：

| 维度 | 合格要求 |
|---|---|
| 回答覆盖 | 回答用户选择的全部争点；相关事实不足时说明条件，不跳过问题 |
| 事实依据 | 明确区分已知事实、用户陈述、假设和待确认信息；不将 unknown 当既成事实 |
| 法律适用 | 法条不仅存在，还须支持具体结论、适用于对应关系和时间；正文与附列依据一致 |
| 数字与引用 | 金额、比例、日期、期限有来源或可核对计算；引用关联到支持它的论断 |
| 可执行性 | 用户能理解下一步、需要补充的材料及会影响结论的条件，不只有泛泛建议 |
| 不确定性 | 信息不足时给必要澄清或有条件结论；重大未核实结论不能伪装为确定结论 |

不得通过删除坏 claim、自动替换引用、降低覆盖率要求来制造通过；不得把 RAG 快答当 Agent 完成。不要新增 LLM judge 或让同一个生成模型自我打分作为验收。

上述是产品质量要求，不代表当前校验器已支持所有表达。例如计算结果即使人工可核对，也可能不满足现有数字来源校验；先按当前契约验收，记录能力缺口。不要借“可核对计算”擅自放行新数字。条件化表达同样不能替代证据或绕过 verifier。

复核结论用 PASS / FAIL / REVIEW，并写原因；REVIEW 不计入 PASS。说明是实现者自查还是独立复核，不将助手判断描述为律师认证。

### 4.3 内容格式与字数

默认顺序为直接结论、必要依据、行动建议；按问题选用自然段或编号列表。复杂问题逐争点展开，简单问题不强套完整报告模板。

- 不设统一最低字数，不用字数作为通过门槛，不强制每个 section 都有内容。
- 篇幅随争点数、必要条件和用户要求变化；现有规则需要篇幅区间时，先抽查真实输出再给建议范围，未观察前不硬定数字。
- 不为凑字数重复法条、免责声明或案情；不为压字数省略关键条件、风险或用户要求的回答。
- 引用紧随相关论断；如保留依据列表，只列实际支持正文的条文，避免将整个检索池展示成“相关法律”。先确认列表来源，再调整显示逻辑；不能只藏起错误依据而保留错误结论。
- 不机械裁剪字符或截断句子。模型输出被 token 限制截断、结构不完整时，识别为失败，不拼成合格终稿。
- 区分内容遗漏与样式偏好：换个标题、稍长或稍短本身不应触发新的失败门禁；只对确有截断、语义缺失或协议错误的情况采取失败处理。
- 格式和篇幅主要通过现有提示词及渲染层改善，不新增润色模型、格式 DSL 或自动重写服务。

### 4.4 交互、性能与代码质量

- 范围选择、事实澄清、运行中、失败和完成要能区分；无效选择应提示可接受输入，不吞掉用户回答。
- 失败提示用普通语言说明结果和下一步；保留诊断错误码，但不要求用户理解内部术语。
- 优先验证选择后恢复、刷新后的真实状态、长任务与断连行为。不用单纯延长超时掩盖卡住的任务，不启动前端改版。
- 仅在发现明显延迟时用已有日志分解耗时；正确性保持后再优化。暂不新增缓存、并发 writer 或性能监控平台。
- 减少重复逻辑、无用分支及误导注释；不以减少行数为指标，不为两处短小重复建通用框架。
- 不削减输入校验、权限隔离、持久化一致性、错误处理或无障碍。既有可用组件优先于新增依赖。

## 5. 评测与停止：防止假改善

复用现有题集、脚本和日志，只补证明确有盲区的案例或断言。比较使用同一条件、同一题集版本；修订金标时保留旧版并重新计算可比基线，不覆盖旧题集救分。

- H01–H05 已经被查看和分析，属于回归材料，不再声称是未见留出集。需要泛化结论时才增加少量未参与设计的新案例。
- 完成率用完成样本数/全部尝试样本数；语义结果同时说明已审核完成样本数。未完成样本不计作语义通过，也不计作“无错误答案”的证据。
- 逐争点方案中，自动评测器选择前五项只能证明该固定选择的结果，不能证明原题全部争点已回答。覆盖判定应依据实际选择范围；未选争点单独记录，不算遗漏或已解决。
- 不将不同题目的完成率当成同题对照；不能因错误码以前出现过，就断言它与本次改动无关。
- 单次差异先记观察或证据不足；没有可比重复运行，不轻率标为 FLAKY，也不因一次转绿宣布可靠性改善。
- 不预设“95% 准确率”。目标修复必须消除目标样本的已确认错误，关键正确对照不能回归；更广泛质量结论必须附样本与局限。
