## 0. 方法纪律（今天已经付过两次学费）

1. **不用它用的那把尺子复算**。它跑 `probe_x.py` 我就换工具/换进程/换目录；同一只脚本重跑一遍得到相同结果，
   只证明"确定性"，不证明"判对"（臂 E 的同进程缓存、凭据的键锚点普查都是这个形状）。
2. **它的报告正文里的每个数字，我都要求它旁边就是产出它的命令**；缺命令的数字按"未交付"处理。
3. **优先读它自己的「我自己造出来的仪器问题」一节**——那是它的自曝面，也是我最该复核的地方（自曝了却没人复算＝白曝）。
4. 它的 `file:line` 与计数**默认视为会过期**：先用 `git -C <候选> rev-parse HEAD` 钉住它当时的树号，
   再按内容重定位（并行会话可能已经推进 HEAD）。

## 2. 我会直接驳回的六种形状（本轮已知的假绿机器）

1. **mock 整个后端**、或假上游的响应形状取自前端类型 ⇒ 循环验证，字段缺口测不出来。
2. **视口 0x0 却报"已测量"**：内置浏览器通道不可用时所有布局读数是 0；要求先给 `innerWidth/innerHeight` 自证。
3. **把 `BACKEND_URL` 指向死端口就当"断网"**：那不是拦截，是打不通。要求逐连接白名单日志。
4. **只查属性字面量当交互验收**：`role="button"`、class 名、tailwind 类都不算现场证据。
5. **对比度按 `background-color` 回溯**：会穿透 `linear-gradient` 取错底色 ⇒ 无合成底色来源的比值不采。
6. **"未跑"写成"通过"或缺席**：任何一腿没跑必须显式写"未跑 + 归因"，不许留空、不许外推。
