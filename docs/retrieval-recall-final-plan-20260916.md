## 4. 剩余选项逐项评估

### (a) 候选生成换武器（更强 embedding）

**现状事实（本次核实）**：
- 本地通道：`BAAI/bge-base-zh-v1.5`（768 维，本地 CPU）；
- **云通道已实现**：`embedding_provider=aliyun`（text-embedding-v4，对应 768 维配置已就位，
  key/端点 settings 齐备）——**换武器不需要新架构，只需配置切换 + 全库重建 + 回归**；
- 资源约束（本次实测）：C 盘 110GB free、D 盘 911GB free、chroma_db 仅 345MB（重建便宜）；
  本地换更大模型（bge-large-zh-v1.5 / bge-m3）受 **HuggingFace 下载**约束（hf-mirror 通道在）。

**评估**：可执行、成本中（云 API 计费或本地下载+重建）、**收益未验证**（oracle 上限 70/78
说明"有空间"，但不等于某个具体模型就能吃到）。**不在本轮实现**。

### (b) LLM 直出条文引用（绕开检索）

**设计要点（留档）**：让 writer/检索器直接产出候选条文号 → **确定性存在性校验**（在库？）
→ 命中的走既有"条号直查路由"进池。项目已有直查路由（1d-2 实证：改写句含"第577条"经直查命中）。

**风险**：幻觉条文号（模型编造不存在的条号）→ 校验层可拦（确定性）；但"库里存在 ≠ 适用"——
直查命中会把不相关条文带进池（比检索污染更精准地引入噪声）。**行为架构级改动**，
须专项设计评审 + 用户拍板。**不实现**。

### (c) 接受 43.4%（推荐，维持 R4）

依据：排序/池深/k/改写四族否证 + KB 在库；剩余 (a)(b) 均无"离线可证收益"前置条件。

## 5. 重开触发器（满足任一即建议以独立批次评估）

1. **embedding 路线**：外部出现"中文法律条文检索"榜单/论文显示某模型（如 text-embedding-v4、
   bge-m3）相对 bge-base-zh-v1.5 有 **≥ 一个明确量级**的检索优势；或业务侧愿意承担
   云 embedding 常驻成本。届时流程：**离线反例先行**（复用 `retrieval_probe.py` 正确口径 +
   §4.1 固定对照：仅 embedding 为唯一目标变量、同题集同 k 同索引版本）→ 增益达标才谈切换。
2. **(b) 路线**：出现"检索完全无路"的高价值场景（如库外条文覆盖率要求）时立项评审；
   前置：确定性校验设计 + 污染评估。
3. **k/排序族**：若未来引入**证据合并层**（rerank 后二次扩额）改变"每问句 top-20 子集"结构，
   需重新评估（当前结构下已否证）。
