## 4. 这一条不是推断，是独立核过的

元典检索 `专利法(2020修正)`：`publication_date = 2020-10-17`、**`effective_date = 2021-06-01`**、
文号 主席令第55号（`id 4c90a01a66d7c6ae…`）。而 `data/laws_clean/中华人民共和国专利法_20201017.txt`
正文末条是「第八十二条　本法自1985年4月1日起施行。」（`id` 另一条 2020 修改决定 `ff0dd604…` 同为 2021-06-01）。
⇒ 三个事实对齐：**修正后的合文本，文末施行条款保留的是原法施行日**；本版的施行日在主文本之外（主席令/修改决定）。

## 5. 因此 E7 的执行形状（建议，尚未开票实施）

1. **主源换成元典结构化字段**：`yuandian_search_laws_and_regulations` 按 `regulation_name` +
   `primary_effect_level=法律` 取 `publication_date` / `effective_date` / `validity_status` / `document_number`，
   99 部一次一部，逐条留 `id` 作溯源（数据票 §3-F 的溯源键在这里正好落地）。
2. **正文正则降级为交叉校验**：只允许它"报警"，不允许它"填值"——
   即 `文末日期 != 元典 effective_date` ⇒ 记一条待人工确认，而不是取任一边自动写入。
   按本盘点，这道校验会命中 36+4=40 部（约 4238 条碎片），**这就是它的价值量级**。
3. **写侧加一条方向不变量**（并进 T3 第④口）：`effective_from < promulgated_at` ⇒ 整批不出。
   法律一般不可能在公布之前施行；这一条正是本盘点里 36 部的探测器，成本一行。
   ⚠️ 若遇"公布日与施行日同日"（PUB 档 6 部）按 `==` 放行，不许写成严格大于。
4. `status` 与 `effective_to` 仍按已签口径逐条判（元典 `validity_status` 到本仓字面值的映射**尚未签字**，
   见数据票 §3-A"部分失效/尚未生效"那一格）⇒ E7 只能先补 `effective_from`/`promulgated_at`，
   **不要顺手动 status**。

## 6. 复算方法（**脚本随票入库**，因为前两版的账都坏在"脚本没留"）

数据面：`data/laws_clean/*.txt` 共 99 个文件（文件名后缀 = 本版**公布日**，非施行日）；
碎片计数取自真实 `chroma_db` 的只读副本 `%TEMP%\fazhi-chroma-ro.sqlite3`，collection 固定
`legal_provisions_te4`（该库另有 `_cos` 一份等量副本，**不按 collection 收窄会把碎片数翻倍**）。
短名规则同 `scripts/import_docs.py:short_source`（去 `_YYYYMMDD` 后缀 + 去 `中华人民共和国` 前缀，
前缀是 **7 个字** —— 本盘点第一版就是切错长度 + 少去日期后缀，导致 99 部对库全部 miss、碎片数报成 0）。

```python
import re, sqlite3, pathlib, os
DATED = re.compile(r"自\s*(\d{4})\s*年\s*(\d{1,2})\s*月\s*(\d{1,2})\s*日[之始]?起?(施行|实施|生效)")
PUB   = re.compile(r"自公布之日起?(施行|实施|生效)")
PFX, RO = "中华人民共和国", os.path.expandvars(r"%TEMP%\fazhi-chroma-ro.sqlite3")
con = sqlite3.connect(f"file:{RO.replace(chr(92),'/')}?mode=ro", uri=True)
cnt = dict(con.execute(
    "select m.string_value, count(*) from embedding_metadata m "
    "join embeddings e on e.id = m.id join segments s on s.id = e.segment_id "
    "join collections c on c.id = s.collection "
    "where m.key='source' and c.name='legal_provisions_te4' group by 1"))
agg = {}
for p in sorted(pathlib.Path("data/laws_clean").glob("*.txt")):
    m = re.search(r"_(\d{8})\.txt$", p.name)
    if not m: continue
    lines = [l for l in p.read_text(encoding="utf-8", errors="replace").splitlines() if l.strip()]
    tail = "\n".join(lines[int(len(lines) * 0.8):])          # 窗口口径：末 20% 行
    s = re.sub(r"_\d{8}$", "", p.stem)
    s = s[len(PFX):] if s.startswith(PFX) else s              # 短名：切 7 个字，别硬写数字
    d = DATED.findall(tail)
    if d:
        iso = f"{d[-1][0]}{int(d[-1][1]):02d}{int(d[-1][2]):02d}"
        b = "LATER" if iso > m.group(1) else "EARLY"
    else:
        b = "PUB" if PUB.search(tail) else "NONE"
    a = agg.setdefault(b, [0, 0]); a[0] += 1; a[1] += cnt.get(s, 0)
laws, frags = sum(v[0] for v in agg.values()), sum(v[1] for v in agg.values())
# 零读数一定是仪器坏了（cwd 不对 / 短名切错），必须报错退出，不许打印 0 继续用
assert laws == 99 and frags == 10266, f"闭合失败 laws={laws} frags={frags}（先查 cwd 与短名规则）"
print(agg, "laws=", laws, "frags=", frags)
```

`backend/venv/Scripts/python.exe <脚本>` —— 解释器在 `backend/venv/`，而 `data/laws_clean` 与 `%TEMP%` 副本
要按仓库根解析，所以 cwd 与解释器路径不同源。09-26 我自己就是把 cwd 摆在 `backend/` 跑，结果 `laws= 0`
（正是下面①号坑的第三次复现），所以脚本末尾加了 `assert` 让零读数直接炸。

期望读数 **`laws= 99  frags= 10266`** 且四档 = `LATER 53/5565、EARLY 36/3549、PUB 6/463、NONE 4/689`
（本票上文那张表就是这条命令的输出，09-26 复跑两次一致）。
**两个数对不上就是仪器坏了，不是数据变了** —— 前两版的三处错（5517 抄成 5117、LATER/PUB 差一部、
