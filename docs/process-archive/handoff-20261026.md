## 8. 技术陷阱（踩过的，别重踩）

1. **PowerShell 引号**：`git commit -m "$(cat <<'EOF' ... EOF)"` 和含 `*` / `|` 的内联 Python 会被 PowerShell 解析吞掉。写临时 `.py` 到 `%TEMP%` 再执行；commit 用多个 `-m`。
2. **ruff 必须排除 `venv-new`**：`.\venv\Scripts\python.exe -m ruff check --extend-exclude venv-new .`。直接 `ruff check .` 会扫进 `venv-new` 报 25 万级错误；用 `--exclude` 又会覆盖 pyproject 的冻结排除项（`scripts/gate5_judge.py` 会被误报）。
3. **所有评测脚本必须 `load_dotenv(..., override=True)`**：否则 shell 里残留的旧 `RERANK_API_KEY` 会盖住 `.env`，recall 会假跌（实测 0.8701 → 0.9562）。
4. **`EVAL_SET` 默认是 28 题**（`data/eval_set.json`）。要 59 题必须显式设 `..\data\eval_set_gen_all.json`。
5. **`EVAL_NO_CACHE=1` 才是独立采样**；反过来，`no_cache=True` 本身**不写缓存**，所以别用它测缓存命中（要验缓存命中得用 `no_cache=False` 连打两次）。
6. **`clarify.decide` 的测试桩必须收 `*args, **kwargs`**：生产签名已加 `has_history` 关键字，位置参数桩会让 16 个用例集体失败。
7. **`backend/.env.example` 必须 ASCII-only**：Windows GBK 解析会出问题，注释只能写英文。
8. **前端验收脚本需要临时用户** `vtest / test1234`（脚本硬编码登录），且运行前 8000 / 3000 必须都在跑；跑完删掉该用户与会话。判据已加固为「消息数 +2、最后一条 >300 字、且不含错误占位」，别退回只看长度的旧写法。
9. **配额关闭后的语义**：`quota_total <= 0` ⇒ `quota_monitored / depleted / below_threshold` 恒为 False；`EVAL_JUDGE_BYPASS_QUOTA=1` 已不再必需，保留为兜底。
10. **存档口径**：`docs/benchmark_results/*2026*.json` 默认被 ignore，只有白名单里的文件入库。新增基线要照抄一行 `!` 规则，否则下一个人看不到证据。
11. **pre-commit 的 ruff 尺子是 `venv-new` + 仓库根配置**：`RUF100` 会把 `# noqa: E402` 判成未启用、`SIM115` 要求 `with open`、`BLE001` 禁裸 `except Exception`。在 `backend/` 下用 `venv` 跑 ruff 通过 ≠ 钩子通过；新脚本入库前按钩子口径复跑（2026-10-27 实测被拦两次）。
12. **`next build` 与 `next dev` 共用 `.next`**：dev 在跑时执行 `npm run build` 会覆盖 dev 的模块文件，页面直接 500/MODULE_NOT_FOUND。先停 dev 再 build；或 build 后 `rm -rf .next` 重启 dev（2026-10-27 UX 审计踩到）。
13. **绝对路径写进 docstring 要用正斜杠**：`C:\Users` 在普通字符串里是 `\U` 转义，脚本会语法错误；用 `C:/Users/...` 或 raw 字符串。
