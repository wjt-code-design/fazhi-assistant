# 检索扩展方案（2026-10-25）· 含对抗性审查

> **执行结果（2026-10-25）**：E0/E1/E3 已跑完。数值全达标（回归集 recall@4 0.8475 → 0.9831，
> 零回归；对外集 0.65 → 0.95），但 **A1 反过拟合审查否决**：39 道非失败题 + 14 道非目标对外题
> **零提升**；9 条触发词在人工改写问法下只有 4 条仍命中。
> **方案 A 验收（第三方 27 条改写问法）**：只有 133、140 达到 ≥2/3 命中并通过检索收益；
> 预注册停止条件（通过词条 <3）触发。**用户裁决：严格执行，不合并；词表扩展路线结束。**
> 详见 `docs/benchmark_results/query_expansion_shadow_20261025.md` 第 8 节。

> 目标：解决「口语提问无法律术语 → 金标条文检索不到」的问题。
> 本方案只动检索输入层，不改回答、不改模型、不改切片。
> 执行前需通过文末对抗性审查的否决项。

## 1. 现状（有数据支撑）

- 回归集 59 题，`recall@4 = 0.8475`（50/59），`recall@1 = 0.678`，`MRR@6 = 0.767`。
- recall@4 失败 9 题：**101、103、108、113、117、133、140、141、153**。
- 共同点：提问里几乎不含法条术语（「朋友送东西反悔」「抵押物还能不能处置」「向证人提问」）。
- 现有链路：`_bridge_query` → `expand_query`（词表 `query_expansions.json`）→
  `query_understand.decompose` → 每单元向量 + BM25 双路召回 → RRF → 云 rerank。
- `expand_query` 目前在**分流前**改写整句，向量与 BM25 都吃扩展词。
- LLM 查询改写（`query_rewrite_enabled`）默认关；历史实测真实路径只救回 2–3/16，
  且本次原型复测出现改写词漂移，**不作为本轮方案**。

## 2. 假设

- **H1**：给 9 道失败题补确定性词条，可救回 ≥5 题，且不产生回归。
- **H2**：若 H1 出现「修几题、坏几题」，原因是扩展词稀释了向量语义；
  把扩展只作用于 BM25 分支（原句走向量）可消除回归。

H2 是备选，不是默认实施项。

## 3. 实验设计

### E0 基线（同进程）

新增 `backend/scripts/shadow_query_expansion.py`：
1. 不 patch 词表，跑 59 题，记录逐题 rank（基线）；
2. patch `retrieval._QUERY_EXPANSIONS` 加入候选词条，再跑 59 题；
3. 逐题对比 rank，输出 JSON + Markdown 到 `docs/benchmark_results/`。

同进程连续跑可减少 rerank 运行间波动带来的假差异。

### E1 全局扩展（默认方案）

候选词条（初稿，全部来自金标条文用语，不由模型生成）：

| 目标题 | trigger | expand（≤12 词） | 主要风险 |
|---|---|---|---|
| 101 | 答应送 | 赠与合同 撤销赠与 权利转移前 | 「送」泛化 |
| 103 | 一审的裁定 | 第二审 裁定 驳回上诉 撤销变更 | 与民事裁定混淆 |
| 108 | 保险公司违法 | 直接负责的主管人员 警告 罚款 撤销任职资格 | 误命中一般保险纠纷 |
| 113 | 处置抵押物 | 重整期间 担保权 暂停行使 | 「抵押物」泛化 |
| 117 | 证人提问 | 询问证人 审判人员许可 质证 | 低 |
| 133 | 取保候审 | 保证人义务 监督 报告 罚款 | 与民法典保证合同混淆 |
| 140 | 犯罪记录 | 密切接触未成年人 查询义务 招用 违法犯罪记录 | 泛化到一般犯罪记录 |

### E2 分支隔离（仅当 E1 有回归时）

在 `retrieval.py` 增加 env 开关 `EXPANSION_SCOPE=all|bm25`，默认 `all`（行为不变）：

- `all`：现状，扩展后 query 同时进向量与 BM25；
- `bm25`：`vector_top(q)` 用原句，`bm25_top(expand_query(q))` 用扩展句，其余 RRF/rerank 不变。

需要单测锁定：默认值行为与现状逐字一致；切换后缓存 key 含 scope。

### E3 验证

- 回归 59 题；
- 对外集 20 题（难例，仅看是否新增失败）；
- 触发词审计：每个 trigger 在 59 题中命中多少题，列出非目标题命中；
- 条件允许时跑 `eval_negative` 的检索侧用例，确认闲聊/超纲不被扩展拉出无关条文。

## 3A. A 阶段预注册（写在收到改写问法之前）

第三方按 `docs/process-archive/reviews/paraphrase_request_20261025.md` 盲写 27 条问法（9 主题 × 3 种口吻）。
以下判定标准在看到问法之前固定，不得事后修改：

1. **触发命中**：某词条必须在同主题 3 条问法中命中 **≥2 条**，才进入合并候选；
   未达标者本轮永久淘汰，**不允许临时放宽/改 trigger 再测**（否则等于用验收集调参）。
2. **检索收益**：对通过命中的词条，扩展后在 3 条问法上的 recall@4 命中数
   必须 **≥ 扩展前**，且至少救回 1 条扩展前未命中的问法。
3. **回归**：把最终选中的词条合入后，59 题回归集必须**零回归**，@1 / MRR 不下降。
4. **停止条件**：若通过第 1 条的词条少于 3 条，判定「词表扩展对本类口语问法收益不足」，
   停止该路线，不再逐条挽救。
5. 27 条问法只用于本轮验收，不进入回归题库；结果全部落盘，不管通过与否。

## 4. 验收（DoD）

必须同时满足：

1. `recall@4 ≥ 0.90`（≥54/59）；
2. **零回归**：基线命中的 50 题中，没有任何一题掉出 @4；
3. `recall@1 ≥ 0.678`、`MRR@6 ≥ 0.767` 不下降；
4. 对外集 20 题无新增失败；
5. 每个 trigger 对非目标题命中 ≤2 题，且能解释原因。

未达标：不合并词表；不得为了达标反复在同一 59 题上调词条（见审查 A6）。

## 5. 对抗性审查（否决项）

| # | 质疑 | 可能错在哪 | 证据/对策 | 否决条件 |
|---|---|---|---|---|
| A1 | 用失败题写词条 = 过拟合 | 只能修这 9 题，换个问法就失效 | 用 39 道非失败题 + 对外 20 题做留出；词条只写金标原文用语 | 只在 9 题有效、留出集无提升 → 否决 |
| A2 | recall 是「任一命中」 | 补金标或放宽 expected 就能刷分 | 实验期间冻结 `expected_articles`；对比文件版本 | 实验前改过金标 → 结果作废 |
| A3 | rerank 有运行间波动 | 单次 +1 名不是真提升 | E0 同进程双跑；只认「未命中→@4 内」和跨 2 名以上变化 | 基线两跑自身波动 >1 题 → 需多次取中位 |
| A4 | 短 trigger 会误触发 | 「抵押物」「行政复议」污染无关题 | 触发审计 + 非目标命中上限 2 题 | 某 trigger 命中 >2 道非目标题且无法解释 → 删除 |
| A5 | 扩展词稀释向量语义 | 修 6 破 4 重演 | H2 分支隔离；先看回归清单再决定 | 有回归且 E2 仍不能消除 → 否决 H1 |
| A6 | 多重比较/挑樱桃 | 逐条试到指标好看，等于在测试集上训练 | 一次提交整批候选；失败则换留出集，不得回炉挑单条 | 出现「删掉坏的那条再试」式迭代 → 结果作废 |
| A7 | 命中≠答对 | 检索进了 @4，回答仍可能引错 | 本方案只声称检索改善；引用指标另行重跑 | 对外宣称「回答准确率提升」→ 越界 |
| A8 | 缓存/时延副作用 | 扩展词改变 query → 缓存 key 变，冷缓存变慢 | 扩展在 key 之前（现有实现）；只接受一次性冷缓存 | 出现同 query 结果不一致 → 停用 |
| A9 | 生产偶合 | `expand_query` 被所有调用方共用 | 默认 scope 不变；新增词条只影响命中 trigger 的 query | 未跑负例就上线 → 否决 |
| A10 | 样本太小 | 59 题里 5 题提升可能是噪声 | 只报「本回归集」结论；不外推整体准确率 | 用该数据对外承诺 → 否决 |

## 6. 已考虑但不采用

| 方案 | 不采用原因 |
|---|---|
| LLM 无条件查询改写 | 已有否证：真实路径救回 2–3/16；本次复测词面漂移 |
| HyDE | 每题多一次 LLM，且有同类不确定性问题；收益不确定 |
| 换 embedding 模型 | 失败原因是词汇不匹配，不是语义模型容量；成本高、影响面大 |
| 微调检索模型 | 无标注训练集；59 题不足以训练 |
| 法律知识图谱 | 工程量大，当前瓶颈用词表即可验证 |

## 7. 实施顺序与回滚

1. 写 `shadow_query_expansion.py`（只读，monkeypatch）；
2. 跑 E0/E1，产出 `query_expansion_shadow_20261025.md`；
3. 达标 → 把通过整批的候选写回 `query_expansions.json`；
4. 不达标 → 若回归明显，做 E2 分支隔离再测；仍不达标则停止，不提交词表；
5. 回滚：词表是数据文件，删除新增条目即恢复；E2 开关默认 `all`，不改变现网行为。
