## 2. 证据要求与隔离边界

### 2.1 什么证据足以支持结论

| 层次 | 适合证明 | 不能单独证明 |
|---|---|---|
| 源码追踪 | 入口可达性、状态传递、历史路径已变化 | 实际运行通过、现役数据安全 |
| 确定性组件用例 | 公式、解析、排序、可控时间、状态转换 | 生产入口真的使用该组件 |
| 隔离集成用例 | 真实认证/路由/持久化/缓存之间接线 | 实际供应商计费、部署网络可达性 |
| 浏览器或容器生命周期用例 | 录音清理、Worker 更新、容器路径 | 其他平台和部署均无问题 |

关键链路至少需要一条证据穿过真实调用方到副作用边界。替身只控制外部模型、时钟、网络响应等不确定依赖，不能把待验证的发布资格、记账、认证或持久化逻辑一起替换掉。

新增回归用例应尽量证明修前会因目标缺陷失败、修后通过。修前含未提交字节、无法可靠还原时，注明限制，并提供独立不变量及故障注入证据；不要声称已完成修前复现。

### 2.2 后续执行时的隔离要求

- 使用临时目录、合成用户、合成法律资料、临时 SQLite/向量集合和可控模型替身。用例外联应能被拦截并暴露为失败，避免误用真实模型。
- 路径配置先于应用导入生效；数据库、缓存、上传目录和端口均归该次运行所有。无法确认隔离时保持未执行。
- R10、R14 需要独立浏览器环境；R11、R12 需要临时部署路径或恢复副本。不得复用正在工作的服务实例或备份原件。
- 不读取真实凭据、用户内容或现役库。执行测试和新增测试文件沿用接手助手已有授权；本文件仅提供验收设计。
- 优先复用现有测试设施，不因本清单引入通用调度框架、事件总线或新的测试依赖。

## 4. 跨模块关联场景

以下是从历史发现推导的**待验证组合风险**，不是新增已复现漏洞。组件分别通过后，仍需按交付范围选择相应场景。没有条件或未选择的场景保留未执行并说明原因。

### X01：重试、解析、保存与门禁（R15、R16、R24、R25）

1. 首尝试先输出可见半截，再输出未闭合 think，随后报可重试错误。
2. 分别安排“后备全空”和“后备完整成功”，保留每次尝试身份与 SSE 顺序。
3. 检查客户端重置、服务端最终正文、消息状态、合同完成标记、答案缓存和 QA 资格。
4. 把同一合成事件序列交给冒烟判定器，错误终止不能凭半截中的正确引用获准。

通过条件：成功只来自完整成功的尝试；失败残片不能获得成功标记或公开资格。若后备实际调用成功但正文被解析器吞掉，必须单独暴露，不能用再调用一次模型掩盖。

**可能漏验：**后端清了 chunks，前端仍显示旧段；脚本忽略 restart，把两次答案拼接；合同路径保留独立旧实现。

### X02：公共 QA 审批、撤回、缓存与重试（R21–R24）

1. A 的个案回答进入候选，先从 B 的三个公开出口查询，确认无自动公开。
2. 用另一条满足既定公开资格的合成 QA 完成批准，预热 QA 直返、答案缓存及提示词检索。
3. 撤回并重读；安排读取在撤回前启动、首正文在撤回后发出的竞争顺序。
4. 对批准注入向量/SQL/失效失败后重试；再测已批准记录重复批准。

通过条件：公开资格取决于已提交的有效批准及版本；缓存命中也验证依赖。没有公开资格的孤儿不应服务，但仍须报告其存储恢复状态。C 的已有防护应保留并回归验证。

**可能漏验：**只测 QA 直返，遗漏答案缓存或作为提示词的召回；撤回 SQL 成功但热缓存仍可服务；首次批准故障受保护，重复批准却留下另一条有效向量。

### X03：调用、取消、故障切换、记账与校准（R08、R09、R15、R19、R20）

1. 对 Agent 或支持 light 的路由分别建立实际调用账本：尝试 ID、模型 key、起止时间、已知 usage/估算来源。
2. 在某次调用完成后取消下一阶段，确认无新的工作启动；检查已经发生的用量是否仍按既定规则入账。
3. 故障切换到另一模型；核对每个 key 的增量及重载后的持久值。
4. 置尽后校准，再路由；用可控顺序分别安排“校准先于扣减”和“扣减先于校准”。

通过条件：取消不启动额外工作，不抹掉已发生且可计量的用量；展示模型不冒充全部调用归属；校准和扣减结果符合明确的先后关系。并发写入若存在覆盖，单测校准公式通过仍不能放行。

**限制：**本地替身账只能证明本地计量，不能证明供应商真实账单；失败请求 usage 不可得时须标估算或未知。

### X04：知识导入、去重、索引与恢复（R17、R18、R11、R12）

1. 临时集合放入同正文、不同法律身份的 seed，保留预期身份集合。
2. 整法替换时注入失败，确认原资料仍可精确与模糊检索；随后成功重跑。
3. 按既有维护约定重启隔离服务或刷新指定索引，再确认不同身份保留、同身份双路合并。
4. 对临时数据制作备份，在副本恢复；核对身份和内容，而非只比数量。

通过条件：导入失败保护原内容；成功和重跑没有身份丢失；恢复工具对损坏正确失败。CLI 导入后重启是历史已有运维约定，不能据此强行新增跨进程通知系统。

**可能漏验：**数据库里还在但服务索引不可查；数量相同却法名/版本被换；备份成功但未包含应用实际使用的配额或知识目录。

### X05：会话切换、附件与录音迟到结果（R05、R06、R14）

1. A 发起详情请求、文档解析和语音识别，均暂不返回。
2. 切换 B 或新建，再按不同顺序返回 A 的成功、失败和识别回调；B 输入新问题。
3. 发送并核对请求体；另测卸载和删除当前会话。

通过条件：所有迟到任务遵守视图所属关系，B 的文本与附件正确，旧失败不会清空 B；实际识别器生命周期结束。WAV 正常停止后的预期转写，应按仍有效的会话操作接受，不能被一刀切丢弃。

**可能漏验：**详情请求加了序号，但文档或识别仍能回填；界面正确，发送时闭包仍取旧附件。

### X06：未知事实、摘要和 Agent 恢复（R02、R07、R08）

1. 用户明确“不知道”某关键事实，保留该未知；随后触发空摘要。
2. 取消后恢复或重新进入同会话，继续已有正常流程。
3. 核对原消息、压缩游标、Agent 状态、writer 输入和最终不确定性表达。

通过条件：未知事实不会因已追问、摘要失败或恢复而消失；不重复追问同一已确认未知；未压缩消息在后续成功摘要中仍被覆盖。普通对话摘要与 Agent 独立状态若并不共享该路径，应记录不可达边界，不能为组合测试改产品接线。

### X07：身份重建、会话资源与限流窗口（R01、R03、R04）

分别完成账号删除重建的旧令牌拒绝，以及伪造头下连续多个失败窗口的锁定。若实际入口允许组合，再由旧令牌访问 B 的会话/媒体，并轮换不可信头发起失败登录。

通过条件：认证与限流各自独立守住边界；修复限流不能被当作旧令牌身份问题的补偿。资源归属通过实际受保护入口验证，不能只看令牌解析报错。

### X08：发布升级与当前视图恢复（R10、R05、R06）

在独立浏览器中安装构建 A，再发布构建 B 并触发 Worker 更新；按既定产品流程重新进入页面，重复 X05 的会话和附件场景，检查缓存版本及资源响应。

通过条件：新构建资源与 Worker 版本符合既定更新策略，切换状态修复真实生效。是否支持无刷新热切换或离线期间保留编辑内容，沿用产品承诺；本清单不新增这类需求。

## 5. 执行顺序与交付判定

建议顺序按影响面组织，不强行改变正在修复的助手排期：

1. **先定目标与适用性。**R01/R02 优先确认；C 的 R21–R24 先识别已有防护及残留，避免重做已存在机制。
2. **数据和身份边界。**适用的 R01、R17、R21–R24；接着 R15 的失败结果保护。
3. **计量与可恢复性。**R08/R09/R19/R20，配合 X03；R11/R12，配合 X04。
4. **局部回归。**其余适用项按矩阵补证据；UI 与 Worker 验收需要对应生命周期环境。
5. **组合验收与门禁。**按实际改动选 X01–X08；R25 必须与最终宣称的验收范围一致。

每个准备关闭的条目须能回答：适用于哪个字节版本、如何触发、正确结果从何而来、执行了什么、证据是什么、剩余限制是什么。

以下情况保持开放或部分覆盖：

- 只有“代码已经改了”，缺少行为证据。
- 只跑过底层单测，生产入口是否接入仍未知。
- 没有核对持久账、公开出口、实际发送请求等关键副作用。
- 同一过程混用了 M/C，或用修复前的旧输出验收修复后版本。
- 条件分支未配置或不可达，却把默认路径通过当成全配置通过。
- 只验收单项，没有覆盖本次改动实际影响的组合边界。

阻断项应结合真实影响、可达性和既有交付要求判定，不能因本文件列出一个历史编号就自动阻断当前交付。非确定的模型质量结论应有独立评测口径，确定性的引用存在性、状态、身份和记账用确定性断言。

### 证据记录模板

~~~text
编号：R__ / X__
交付对象：绝对路径 / HEAD / 最终差异或关键文件 SHA-256
适用性：成立 / 已有防护 / 条件适用 / 不适用 / 待确认
适用性依据：入口、配置与源码位置

修后结果：退出码、事件、响应、持久化及公开读取结果
证据：脱敏日志/输出/截图/产物路径
结论：未执行 / 通过 / 失败 / 部分覆盖 / 无法判断
限制与未决项：缺哪层证据，谁需决策，何时补查
~~~
