## 3. 判定口径

评审六个维度：事实忠实、问题覆盖、规则及引用对应、条件与不确定性、数字与金额、表达与可执行性。每项结论采用“确认问题 / 局部合理 / 待核 / 未覆盖”，不编造统一百分制总分。

以下任一情况应阻止判定该回答“质量验收通过”：关键结论依据了未给出的事实；摘要改写了正文的成立条件；引用条文没有支持其旁边的具体结论；未知金额被输出为确定金额。字数、结论卡样式、引用次数不能抵消这些问题。

## 4. 确认问题

### Q7-01：C08 结论卡把保证期间缺失当作保证方式缺失（P2，高置信）

位置：`answers/C08.txt:4`；正文第一个分析段。

题面只说合同没写“保证期间”。结论卡却写“合同没写保证期间，依法推定你承担一般保证责任”。正文随后又以“对保证方式没有约定或者约定不明确”为一般保证的条件，并使用“如果合同只笼统写担保”的假设。

**可确认问题：** 题面未给出保证方式；结论卡将两个不同条件合并，并把正文的假设变成对用户的结论。即便正文后面解释了区别，先读结论卡的用户仍可能得到错误判断前提。

最小改进：分别询问/列出“保证方式条款”和“保证期间条款”；结论卡保持条件句，不得仅依据没写期间推导方式。此项首先是输入与内部逻辑问题；本轮未完成民法典相关条文的官方全文逐条核验，不宣称已完成保证法律问题全覆盖。

验收反例：保持“未约定期间”不变，分别加入明确连带责任、方式未约定、条款未知三个版本；输出不得统一认定为一般保证。

### Q7-02：N01 将常见作业方式写成已知案件事实（P2，高置信）

位置：`answers/N01.txt:11`。

题面只有上门安装、未系绳、梯子摔伤等信息。回答写“师傅自带工具设备、自行决定操作方式与流程”，随后说“装空调师傅符合这一特征”，据此倾向承揽关系。

**可确认问题：** 工具由谁提供、谁控制作业流程、如何计价均未由题面提供。后面虽然增加“若约定固定报酬”等条件和另一种关系分析，前面的陈述仍把典型场景当作本案事实。这里不是断言最终关系一定认错，而是判断过程的事实来源不可靠。

最小改进：把这些内容转成待确认事实或显式假设；在确认之前并列两种适用路径。正文“明显过错”“主要后果”等强判断也应结合事故原因和现场条件核实，不能仅凭未系绳自动完成责任比例判断。

验收反例：分别提供用户供梯并逐步指挥、师傅独立自带工具计件收费，以及两者均未知的版本；结论强度须与输入匹配，未知版本不得自行补事实。

### Q7-03：C04 的真实条号没有支持所绑定的一般赔偿命题（P2，高置信）

位置：`answers/C04.txt:4`、`:14`；该答案后续讨论违约金调减时又使用同条。

在预付款分支，回答用合同编通则解释第六十五条支持一般差价损失及赔偿衡量。该条处理的是当事人要求减少过高约定违约金的司法调整，不能仅因其提及民法典第五百八十四条，就把整条的适用范围扩展为普通损害赔偿规则。正式解释也把违约损害赔偿与违约金调整分别编排。来源：[最高法答记者问](https://www.court.gov.cn/zixun/xiangqing/419402.html)、[天津海事法院公布的正式解释文本](https://tjhsfy.tjcourt.gov.cn/article/detail/2023/12/id/7716250.shtml)。

**影响：** 条文存在、条号正确、文本相关，仍可能发生结论与规范不对应；只做引用存在性检查会漏掉。此处不否定用户可能有损害赔偿请求，只否定这段具体引证足以直接支撑全部论证。

最小改进：逐个命题核对规则适用前提；将一般损失赔偿与违约金调整分开。对于“缺乏直接条文依据”，应准确说明是本次检索未取得依据还是法律本身不明确，避免两者混淆。

1. **路径标签不够准确。** 原质量报告标题含 Agent，但驱动实际是快车道近似调用；应分别公布 Agent 与快车道结果。

4. **成功样本分数与请求成功率分开。** 原报告存在失败后重跑记录；不能从最终答案文件齐全推断每次请求均成功。
5. **评测产物需要版本绑定。** answers 文件会被同 ID 后续运行覆盖；runs.jsonl 没有答案哈希和完整配置绑定。本轮用快照哈希弥补追溯，原运行的严格归属仍有限制。
6. **未采纳旧 93 分作为本轮结果。** 六份是针对风险选择的单次输出，不具备总体质量估计所需的代表性和稳定性证据。
